Local-only example

Two files, no backend. Comments are saved in your browser.

Try it: select any run of text in this article. A Comment bubble appears — click it and you drop into commenting mode; add your name and a note. The passage gets highlighted; click the highlight to reopen the thread. The control (bottom-right here) switches between Viewing and Commenting and exports as Markdown.

How anchoring works

A comment is tied to the words you selected, not to a pixel position or a DOM path. When the layer saves a thread it stores the exact quote plus about forty characters of context on each side. On the next load it searches the page for that quote and, if the text appears more than once, uses the stored context to pick the right occurrence. Edit the surrounding prose and the highlight still lands, as long as the quoted words survive.

Commenting on links

Navigation, buttons, and code blocks are excluded from selection, so you comment on content rather than on chrome. Links are different: you can comment on link text too. In commenting mode the document's links go inert, so selecting a link like this one is clean and never navigates away. Switch back to viewing and the same link works normally. Mark any element with data-cmt-skip to keep it out of the commentable text.

Where comments live

In this example they live in localStorage, scoped to this browser and this docId. Nobody else sees them. To run a shared team review, see the backend guide and point backend at the Worker — the front-end code does not change beyond that one config line.
